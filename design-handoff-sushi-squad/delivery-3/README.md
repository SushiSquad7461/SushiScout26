# Handoff: SushiScout 26 — Sushi Squad 7461 rebrand

## Overview

SushiScout 26 is Sushi Squad 7461's FRC/FTC match-scouting app (Flutter,
Firebase). It currently ships as stock Material 3: every colour is machine-
generated by `ColorScheme.fromSeed` from a single salmon hex `#FA8072`, the type
is Inter, and `Icons.sports_soccer` stands in as the app's logo. There is no
brand layer at all — which is precisely the complaint that started this work:
*"it just doesn't look like something Sushi made."*

This handoff replaces that with the team's real identity, taken from the **Sushi
Squad Design Initiative** (the team's own brand document): the "Bubblegum
Forest" palette, Sushi Sans + Mohave type, square geometry, the colour bar as
the ownership mark, and the four mascots in place of a logo.

It also introduces a `TeamBrand` model so a second team's identity can be added
later as a single const — a requirement the team stated up front.

## About the design files

Two different kinds of file are in this bundle, and they are used differently.

**`design-reference.html`** is a **design reference**, not production code. It is
a single self-contained HTML file showing all eleven screen states side by side
at 390×844 (plus one 1280×800 desktop frame). Open it in a browser. It exists so
you can see the intended result; do **not** port its markup.

**`dart/`** is different, and unusual for a handoff: it is **real Dart, written
against the actual repository**, and is intended to be copied into the project
as-is. Every file was written after reading the corresponding file in
`SushiSquad7461/SushiScout26@master`, preserves that file's existing behaviour,
and is documented against it. Treat it as a starting implementation to review,
not as pseudocode to translate.

**`SPEC.md`** is the implementation instruction set — file manifest, per-file
edits, schema coverage, known gaps, verification. **It is the authoritative
document; this README is orientation.** Where they disagree, follow `SPEC.md`.

### Target repository

`SushiSquad7461/SushiScout26`, branch `master`, app root `frontend/`. Flutter,
Dart SDK `^3.10.4`, Riverpod, Firebase (Auth, Firestore, Functions), `google_fonts ^7.0.0`.

Suggested branch: `design/sushi-squad-brand`.

## Fidelity

**High-fidelity.** Final colours, type, spacing and geometry. Every value comes
from the bound Sushi Squad 7461 Design System (`--ss-*` tokens) or from the
Design Initiative directly — none were invented. The Dart mirrors those values
because Flutter cannot consume the CSS tokens; `SPEC.md` §9 is the mapping.

Recreate the intent, not the pixels: this is a Material 3 app and stays one.
Restyle through `ThemeData` wherever possible rather than hand-styling widgets.

## Hard constraints — read before writing code

These are the three things that would break the app if ignored.

1. **The scouting forms and the database schema do not change.**
   `frc_rebuilt_form.dart` and `ftc_decode_form.dart` are not edited at all.
   Nothing in this change reads or writes `gameData`, `MatchReport`,
   `toFirestore`/`fromFirestore`, or any Firestore path. The 5-page wizard, the
   field set, the validators and every `gameData` key stay exactly as they are.
   The team's instruction was explicit: forms are *recoloured and rebranded,
   never redesigned*.

2. **Do not rewrite `dashboard.dart`.** It is ~700 lines of export, auth, sync
   and navigation logic. `SPEC.md` §4 gives five surgical edits. In particular
   its app bar is a `SliverAppBar.medium` inside a `CustomScrollView` carrying
   the connection chip, search, export and the overflow menu — swapping in a
   `PreferredSizeWidget` silently deletes all four plus the collapse behaviour.

3. **Preserve original functionality.** Every callback, provider read, validator,
   error path and async guard stays. Where a widget is restyled, its behaviour is
   untouched. The rewritten `login_screen.dart` and `settings_screen.dart` in
   `dart/` already do this — diff them against the originals to confirm before
   assuming otherwise.

## Screens / views

Eleven frames in `design-reference.html`, in this order. Frame labels match the
`data-screen-label` attributes in the file.

### 01 · sign in — `login_screen.dart`

*Purpose:* authenticate. Google on mobile/web; email + password on desktop.

*Layout:* full-bleed `MascotPlate` (peepo, 300pt) at the top under the status
bar → 8pt colour bar → ink `#000000` body, 24pt padding. Wordmark "SushiScout
26" at 46pt display, `line-height 0.94`; subtitle in Mohave Light italic 17pt
lilac; sign-in button pinned low; helper line centred beneath it.

*Components:* the button is a 60pt-tall `FilledButton`, white fill, ink label,
square corners, label 18pt display with `0.1em` tracking. **No icon, no
checkbox** — a Google glyph is not in the brand's asset set and was removed
deliberately.

*States:* `authState.hasError` renders a 2px error-outlined banner above the
button. Loading swaps the label for a 20pt spinner + "Signing in…". Desktop
branch adds two fields, an obscure-password toggle and "Forgot Password?".

### 02 · match log — `dashboard.dart`

*Purpose:* the home screen. Every scouted match, newest first.

*Layout:* ink app bar with a 30pt single-colour mascot mark at the leading edge
→ 6pt colour bar → event row (`2026 casj`, sync summary) divided by a 2.5px
rule → card list, 18pt gutters, 11pt gaps → full-width ink action bar.

*Match card:* 2.5px ink border, square. Left-to-right: 4pt alliance strip
(`#c10000` red / `#56cbf9` blue) · 48pt solid-ink badge with the match number in
display type reversed to white · title `q28 · team 254` at 17pt display · summary
`auto 8 · tele 24 · climb` 14pt Mohave oyster · scouter line 13pt Mohave Light
italic · 12pt sync square at the trailing edge.

*Action bar:* replaces `FloatingActionButton.extended`. 66pt tall, full width,
solid ink, label "scout match" 21pt display `0.1em`, with a 44×7pt colour bar
beside it. Rationale: a full-width bar is a faster target than a FAB during a
2.5-minute match, and a rectangle spanning edge to edge is the Initiative's
geometry rather than Material's.

### 03 · scout · page 2 of 5 — forms (**not edited**)

Shown only to demonstrate that the existing wizard repaints correctly through
`ThemeData`. Event-code app bar · `MatchTimer` counting down from 2:15 with its
phase chip · "Autonomous" title + 2.5px rule · Auto Fuel `CounterCard` with its
step control · L1 Hang switch row · Back / 5-dot page indicator / Next.

`CounterCard` keeps the **original** layout exactly — centred label, optional
helper, centred `[− value +]` with the same 80pt value slot and **56pt** buttons.
Only the paint moved: the 10%-alpha accent wash behind the card is gone (an
accent tint on a surface is the one thing the Initiative rules out) and the
accent now sits on the label and the button outlines.

### 04 / 04b / 04c · match details — `match_details.dart`

*Purpose:* read one report back.

*Layout:* 200pt **ink** header — not an alliance flood — carrying an 88pt solid
alliance badge, an outlined alliance pill and the collapsing team name. Then 8pt
colour bar → scouter row with a mascot mark, the FRC/FTC chip and the sync chip →
a stack of section cards, each with a 4pt alliance strip, a title, a 2.5px rule
and label/value rows.

04 is FRC (Autonomous, Teleop, Traversal, Shooting Range). 04b is the scrolled
state (Performance, Comments, the robot-died warning). 04c is the FTC branch —
different sections entirely — and doubles as the blue-alliance and
not-yet-synced example.

Two shape changes only: the badge loses `BoxShape.circle`, and `_RatingRow`'s
five stars become five 14pt squares filled to `value`.

`SPEC.md` §8 maps all 18 `gameData` keys to the section and label that displays
them. Labels are verbatim from the existing file; none were renamed.

### 05 / 05b / 05c · settings — `settings_screen.dart` (new)

*Purpose:* profile, appearance, team, export.

**The one structural change:** this was a `DraggableScrollableSheet`
(`settings_sheet.dart`) and becomes a pushed route. Sections keep their original
order and content — Profile (name, event code + helper, program type) ·
Appearance (theme mode, then the brand picker where the colour-seed chips were) ·
Team (active team, invite code with copy + regenerate, team list, join/create) ·
Sheets export behind `isTeamAdminProvider` · Done.

Sign-out stays in the dashboard's `PopupMenuButton`, where the original puts it.
Do not duplicate it here.

The colour-seed chips become brand tiles reading `TeamBrands.all`, plus an "add a
team" placeholder. Same preference key (`PrefKeys.colorSeed`), same
`setColorSeed` call — the values are brand ids now, and `TeamBrands.byId` falls
back to Sushi Squad for the legacy values already on scouts' devices.

### 06 · dark

Same duality inverted: paper on ink, 2.5px white rules, badges reversed. Theme
mode still follows the system (`themeMode` is untouched).

### 07 · empty state

Full-bleed `MascotPlate` (daimler, 260pt) where a circular `Icons.ramen_dining`
container was. Both existing strings are kept — they already read in the team's
voice.

### Desktop / web

1280×800. 232pt ink sidebar (mascot mark + wordmark, colour bar, nav, scout
identity at the foot) and a dense table — match, team, alliance, auto, tele,
endgame, scout, sync. Included because the team asked for desktop to be
considered; it is a direction, not a specified build.

## Interactions & behaviour

The Design Initiative is a print document and specifies **no animation, hover or
press behaviour**. The coherent extension, and what this design assumes, is an
instant hard state change — swap to an accent fill, or invert black/white — with
no transition, no shape change, no shadow, no fade.

Concretely: `splashFactory` stays `InkRipple`; nothing grows a shadow on hover;
selected states invert to ink-on-white; focus is a 3px french outline. Existing
`AppHaptics` calls are preserved as-is. Loading, error, empty and offline states
all keep their current triggers and copy.

## State management

Riverpod, unchanged. No new providers, no changes to existing ones.

The one addition is `BrandScope`, an `InheritedWidget` in `team_brand.dart` that
makes the active `TeamBrand` reachable via `BrandScope.of(context)`. It is what
keeps `CounterCard`'s constructor unchanged so the form call sites compile
untouched. Wrap the app once in `main.dart` (`SPEC.md` §3).

Brand selection persists through the existing `PrefKeys.colorSeed` string.

## Design tokens

Palette — **"Bubblegum Forest"**. Black and white are the primaries and carry
the majority of every surface; oyster is the only grey; the four accents exist
*only* to highlight an element or add brand presence, never as a surface fill.

| Token | Hex | Role |
| --- | --- | --- |
| `--ss-white` | `#ffffff` | primary |
| `--ss-black` | `#000000` | primary |
| `--ss-oyster` | `#4f4f4f` | secondary — rules, panels, secondary type |
| `--ss-arita` | `#81f4e1` | accent 1 — synced / confirmed |
| `--ss-dodger` | `#56cbf9` | accent 2 — also blue alliance |
| `--ss-french` | `#ff729f` | accent 3 — highlight, links, focus |
| `--ss-lilac` | `#fcd6f6` | accent 4 |
| `--ss-splash-red` | `#c10000` | red alliance (in the Initiative, outside the accent set) |
| `--ss-mute-grey` | `#c4c4c4` | de-emphasised text **on ink** |

Accents always appear in the order arita → dodger → french → lilac, or its exact
reverse. That ordered run *is* the colour bar.

**Alliance colours sit outside the brand deliberately** — red has to read as red
in the stands, so french (pink) cannot serve. Red is `#c10000`, which the
Initiative already uses; blue is dodger.

**Type.** Display: **Sushi Sans** (bundled, `assets/fonts/SushiSans-Regular.ttf`),
Poppins as the brand's declared secondary. Body: **Mohave** (Google Fonts), IBM
Plex Sans Condensed as secondary. Mohave **Light italic (300)** is the
document's dominant voice and carries all helper and secondary copy.

Nothing is bold — the Initiative sets everything at 400. Hierarchy comes from
size and from the blank line under a heading.

Scale as used here: 46/40/30 display for titles · 21 app-bar title · 17 card
title · 16/15/14 labels with `0.1–0.16em` tracking · 17/15/14 body · 13–14
helper italic · 40–54 numerals, tabular.

**Casing.** Headings and section titles are **lowercase**, per the Initiative's
own (`about this document`, `logoless`, `clearance`). Body copy is sentence
case. Event codes are lowercase (`2026casj`). Two exceptions, held consistently:
the team name (three sanctioned forms — pick one) and programme acronyms, which
stay uppercase (`FRC`, `FTC`). Flutter has no `text-transform`, so this is just
how the literal is written — do not add `.toUpperCase()`.

**Geometry.** Radius `0` everywhere — `AppTheme.cardRadius` and `buttonRadius`
are `0`, so existing `BorderRadius.circular(AppTheme.cardRadius)` call sites go
square with no edit. A **2px rule** replaces tinted elevation; section rules are
10px. No shadows, no elevation overlays, no capsules, no blur.

**Spacing.** `4 / 8 / 16 / 24 / 32 / 48` as `AppTheme.spacingXs…Xxl`. Minimum
touch target 48pt.

## Assets

| Asset | Origin |
| --- | --- |
| `dart/assets/fonts/SushiSans-Regular.ttf` | The team's own face, supplied by the user. |
| `dart/assets/mascots/{nori,peepo,sparkie,daimler}.svg` | Extracted from the Design Initiative's vectors — **not redrawn**. Single-path, `fill="#000"`, tinted at runtime via `ColorFilter`. |

Team 7461 is **deliberately logoless**: any of the four mascots may stand in for
a logo, which the Initiative frames as *"unity in individualism as opposed to a
stoic, undynamic image."* Rules, all enforced by `BrandMascot` / `MascotPlate`:
a mascot in small form must be a **single colour**; it keeps a margin of **1/8
its own width** on every side; it may be rotated or scaled but **never stretched
non-uniformly**.

No icon system exists in this brand. For UI icons the app keeps Material icons
at their current sizes — do not draw mascot-styled approximations.

## Known gaps — read before starting

Full list in `SPEC.md` §11. The three that will bite:

1. **Sushi Sans has missing glyphs, measured.** Ink pixels at 80px: `a` 1327,
   `0` 1484 — but `·` `/` `-` `'` `"` `+` `:` `;` `,` `?` `<` `>` are all **0**.
   The face declares an advance width for each but carries no outline, and
   neither the browser nor Flutter falls back for a glyph that exists-but-is-
   empty; they draw nothing and leave a gap. `q28 · team 254` renders
   `q28  team 254`, and a timer set as `2:03` renders `203`.
   Never put those characters in the display face — use
   `AppTheme.displayRun(brand, parts, separator: ' · ')`, which sets the words
   in Sushi Sans and the separator in Mohave. Worth asking the team to add the
   glyphs; that deletes the workaround.

2. **Contrast follows the surface.** Oyster on white is 8.9:1 but on black only
   2.56:1 — always read muted text from `brand.mutedFor(brightness)` /
   `colorScheme.onSurfaceVariant`, never hardcode oyster. French on white is
   2.57:1: correct for links and fills, wrong for anything read at a glance (a
   timer, a field label) — those go `colorScheme.onSurface`.

3. **`secondaryContainer` is lilac on purpose.** `ConnectionStatusBar` and
   `ConnectionStatusChip` paint themselves from that pair; mapping it to the
   surface colour makes the "Uploading N reports…" band invisible white-on-white.
   Don't "fix" it back to a neutral.

Also: `AppTheme.getSeedColor` / `lightTheme` / `darkTheme` / `salmonSeed` and
the other seed constants are kept as `@Deprecated` shims purely so
`settings_sheet.dart` compiles until step §4e deletes it. Remove them together;
`flutter analyze` will emit deprecation infos until you do.
